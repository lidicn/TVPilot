## 二、拔 sock 后哪些功能会坏：docker CLI 调用点全量排查

### 2.1 排查方法

- 对象：本次快照 `doc/snap_tvpilot_server_20260921T0815Z.py`（= 容器现跑版本，131,965 字节）
- 搜法：
  1. `grep -n "docker"` 全文件 → 命中 **4 行**
  2. `grep -n "subprocess|go2rtc|check_output|Popen|shell=True"` 交叉验证 → 所有 subprocess 调用点逐一过堂
  3. 无 `shell=True`；无 `Popen`；无 `check_output`；无 f-string 拼接 docker 命令
- 容器内实测：`docker` CLI 存在于 `/usr/bin/docker`（client v25.0.5），当前经 sock 能连通 server（v28.5.2）。**CLI 本身在镜像里，拔 sock 不影响 CLI 存在性，只影响它连 daemon。**

### 2.2 真调用点（共 2 处，同一函数内）

| # | 文件:行号 | 代码 | 所在函数 / 触发路由 | 拔掉 sock 后的预期行为 |
|---|---|---|---|---|
| 1 | `tvpilot_server.py:321` | `subprocess.run(['docker', 'cp', tmp_yaml, 'go2rtc:/config/go2rtc.yaml'], capture_output=True, timeout=10)` | `_do_refresh_rtsp()`（定义于 :161）<br>由 POST `/api/iptv/refresh_rtsp`（路由 :3084-3091，线程在 :3089）触发 | **报错但被吞掉**。`docker cp` 会失败：`Cannot connect to the Docker daemon at unix:///var/run/docker.sock. Is the docker daemon running?`，returncode 非 0。**但代码没有检查 returncode**（返回值直接丢弃），不抛异常，继续往下走。 |
| 2 | `tvpilot_server.py:323` | `subprocess.run(['docker', 'restart', 'go2rtc'], capture_output=True, timeout=30)` | 同上，同一函数紧接 :321 | **报错但被吞掉，且对外静默报成功**。`docker restart` 同样连不上 daemon，returncode 非 0。**代码同样不检查返回值**，继续执行 :325 `time.sleep(5)`、:326 `log('go2rtc 已重启')`，然后 :333-334 把 `st['running']=False`、`st['last_success']=True`。 |

**净效果（拔 sock 后调用 `/api/iptv/refresh_rtsp`）：**
- HTTP 层：路由立即返回 `200 {"ok": true, "message": "RTSP 刷新已开始，约40秒完成"}`（:3090）—— 和现在一模一样。
- 后台线程：~40 秒后跑完，`/api/iptv/refresh_status`（:2481-2486）会报 `last_success: true`、`message: 完成！N 个频道已刷新`。
- **实际**：go2rtc.yaml 根本没被 cp 进去，go2rtc 容器根本没被重启。RTSP 流配置还是旧的。
- **这就是用户点名的"静默成功"**：总架构师裁掉这条路由的理由成立 —— 拔 sock 后它**应当**报错，但当前代码会继续谎报成功。
