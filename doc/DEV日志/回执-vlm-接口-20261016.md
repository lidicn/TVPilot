# TVPilot VLM 看图接口开发回执

> 开发时间：2026-10-16
> 版本：0.9.1（新增 VLM 工具）
> 状态：✅ 完成

---

## 一、设计思路

**TVPilot 只负责截图，上层 agent（豆包）自己看图理解。**

不需要 TVPilot 自己调 VLM API，避免重复实现和依赖问题。
这样更简单、更稳定，也更灵活。

---

## 二、交付内容

### 新增 MCP 工具：tv_understand_screen

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| prompt | string | - | 保留参数，上层 agent 自己的提问 |
| width | integer | 480 | 截图压缩宽度，省 token |

**返回**：
- image_base64: 截图的 base64 编码（PNG/JPEG）
- image_width: 截图宽度
- image_bytes: 截图字节数
- format: 图片格式（png/jpeg）
- note: 提示上层 agent 直接看图

---

## 三、使用方式

上层 agent 调用 `tv_understand_screen`，拿到截图 base64 后：
1. 自己看图理解界面
2. 决定下一步操作（点哪里、输什么）
3. 调用 TVPilot 的其他工具执行操作

**示例流程**：
```
用户："打开搜索，搜全资进组"
  ↓
agent: 调 tv_understand_screen()
  ↓
agent: 看图 → "右上角有个放大镜图标，那是搜索"
  ↓
agent: 调 tv_tap(x, y) 点搜索
  ↓
agent: 调 tv_input_text("全资进组")
  ↓
agent: 看图 → "搜索结果出来了，第一个就是"
  ↓
agent: 调 tv_tap(x, y) 点第一个结果
```

## 五、为什么不自己调 VLM API

1. **重复造轮子**：上层 agent 已经有 VLM 能力了，不需要 TVPilot 再调一次
2. **依赖问题**：doubao2api 代理不支持多模态（发图片 502）
3. **更灵活**：上层 agent 可以边看边想，决定下一步操作
4. **更稳定**：少一层 API 调用，少一个故障点
