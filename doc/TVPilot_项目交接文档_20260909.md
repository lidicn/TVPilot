## 一、项目概述

### 1.1 产品定位
TVPilot 是一套智能电视中控系统，实现：
- **人脸识别登录**（arcface）→ 个性化电视节目列表
- **语音换台**（遥控语音 + PWA 手机端语音）
- **与豆包管家联动**（LLM 通过工具层控制电视）
- **观看历史整理**（供 memory-agent 使用）
- **截图接口**（供豆包管家获取当前画面）

### 1.2 子项目组成
| 子项目 | 包名/容器名 | 端口 | 职责 |
|--------|------------|------|------|
| **TVPilot 服务端** (zap) | 容器 `tvpilot` | 8090 | HTTP API、MQTT、换台调度、保活巡检、PWA 界面 |
| **mytv** | `com.tvcam.mytv` | 10481 | 电视端播放器、频道列表、EPG、HTTP 控制 |
| **arcface** (tvcam) | `com.example.arcfaceandroid` | 8080/8081 | 人脸识别、无障碍服务、截图、HTTP 接口 |
| **go2rtc** | 容器 `go2rtc` | 1984 | RTSP→HLS/RTSP 转码，音频 AAC 转码 |
| **PWA** | TVPilot 容器内 `/pwa` | 8090 | 手机端快捷换台、语音换台 |

### 1.3 架构关系
```
                    ┌─────────────────┐
                    │   豆包管家 LLM   │
                    └────────┬────────┘
                             │ HTTP 工具调用
                    ┌────────▼────────┐

                    │  (zap 服务端)    │
                    └───┬──────┬───────┘
                        │      │
           ADB/HTTP     │      │ HTTP /api/zap
                        │      │
              ┌─────────▼──┐ ┌─▼──────────────┐

              │  :8080/8081 │ │  (电视播放器)    │
              │  人脸识别    │ └────────┬────────┘

              └─────────────┘          │

                                  │  RTSP 转码    │
```

### 3.4 go2rtc

**容器**：`go2rtc`，端口 1984
**配置**：`/config/go2rtc.yaml`（容器内）
**认证**：lidicn / <REDACTED>

#### 作用
将电信 IPTV 的 RTSP 源转为 HLS/RTSP，供 mytv 播放。

#### 关键配置（ffmpeg 转码命令）
```yaml
streams:
  频道名: exec:ffmpeg -rtsp_transport tcp -i "{rtsp_url}" -fflags nobuffer -flags low_delay -codec:v copy -codec:a aac -b:a 128k -ar 48000 -ac 2 -rtsp_transport tcp -f rtsp {output}
```

**音频转码原因**：原始 RTSP 音频是 **MP2 编码**，HLS/TS 不支持 MP2，必须转 AAC。
- 之前用 `-an`（去掉音频）→ mytv 没声音
- 用 `-codec:a copy` → MP2 被丢弃，没声音
- **当前正确**：`-codec:a aac -b:a 128k -ar 48000 -ac 2`

#### 频道数
98个（97个正常频道 + 1个测试），配置文件：`go2rtc_97channels.yaml`

## 四、IPTV 源与 RTSP 管理

### 4.1 频道来源
- 电信 IPTV 抓包获取 RTSP 地址
- 共97个频道（广东本地、央视、省级卫视、体育、少儿等）
- RTSP URL 含 token，约**4天过期**

### 4.2 RTSP URL 结构
```
rtsp://.../.../accountinfo=~~V2.0~{段3频道token}~{段4用户token}~{段5ExtInfoPC{base64}:{时间戳},...}
```
- 段3：频道专属 token
- 段4：用户 token，**全局共享**，约4天过期
- 段5：扩展信息

### 4.3 自动刷新（方案 A）
**脚本**：NAS `/opt/tvpilot/auto_refresh_rtsp.py`
**Cron**：`0 3 */3 * *`（每3天凌晨3点）
**流程**：
1. 从当前57频道配置中提取最新段4用户token
2. 批量更新97频道的 RTSP URL（替换段4）
3. 更新 go2rtc 配置并重启
4. 全流程约40秒

**Windows 副本**：`D:\Documents\WorkSpace\TV_CAM\tmp\auto_refresh_rtsp.py`

### 4.4 方案 B（认证 API 逆向，进行中）
目标：通过电信 IPTV 认证 API 程序化获取全新 token，不依赖抓包。

**5步流程**：
1. 获取 EPG 服务器 → ✅ 成功（eds.iptv.gd.cn:8082）
2. 获取 EncryToken → ❌ 阻塞（返回 invalid_client，clientId 未找到）
3. DES 加密 → ✅ 算法已逆向（key=MD5(password)[:24], DES/ECB/PKCS5）
4. 获取 access_token → ⏳ 待步骤2
5. 批量更新频道 → ✅ 复用方案A逻辑

**阻塞点**：clientId 已试11个候选值全部失败（MAC/stbId/包名/IMEI/品牌等）。需从电视 logcat 抓实际 EncryToken 请求或深入反编译。

**存档文档**：`E:\NAS\TVPilot\doc\电信IPTV_认证API逆向_方案B存档.md`

## 十、接手建议

### 10.1 第一步：验证环境
1. 确认电视在线：`adb connect 192.168.2.238:5555`
2. 确认 NAS 容器：`ssh lidicn@192.168.2.200 "docker ps"`
3. 测试 mytv 播放：启动 mytv，看能否正常播放
4. 测试换台 API：`curl -X POST http://192.168.2.200:8090/api/zap -d '{"channel":"中央一台"}'`

### 10.2 第二步：聚焦 P0 问题
当前最影响体验的是 **mytv 播放性能**（换台慢、黑屏、音画不同步、3002错误）。建议：
1. 用 PotPlayer 或飞牛影视播放 M3U（`http://192.168.2.200:8090/iptv/source.m3u`），判断是源问题还是播放器问题
2. 如果第三方播放器流畅 → 优化 mytv ExoPlayer 配置（缓冲、解码、渲染）
3. 如果第三方也卡 → 优化 go2rtc 转码（考虑降低分辨率/码率、或换转码方案）

### 10.3 第三步：重建 TVPilot 镜像
当前 TVPilot 代码是临时 docker cp 的，容器重建会丢失。需要：
1. 编写 Dockerfile（如果没有）
2. 构建镜像：`docker build -t tvpilot:v0.7.1 .`
3. 更新 docker-compose 或启动脚本

### 10.4 注意事项
- **不要**给 mytv 加后台保活（会误打断用户），只在换台时唤起
- arcface 保活用**广播**后台启动服务，不要 `am start` 主界面
- mytv 缓存在 `cacheDir`，不是 `filesDir`
- RTSP token 约4天过期，NAS cron 每3天自动刷新
- 原始 RTSP 音频是 MP2，必须转 AAC，不能 copy 或 -an
