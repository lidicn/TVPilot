# 调研笔记：开源 ADB + LLM 电视/手机操控 agent（2026-09-22）

## 一句话结论
**没有现成"控电视"的开源 LLM agent**——赛道全是手机/模拟器。最值得抄的不是整套 VLM agent，而是一类轻量 ADB 桥（读 UI 树 + snapshot-ref-act）。我们的最优路线：**确定性脚本管高频动作，读树管菜单导航，VLM 只做兜底**。

## 三派方案对比

### A 派：端到端 VLM（截图 → 模型直接出动作）
| 项目 | 来源 | 要点 | 对我们 |
|---|---|---|---|
| **UI-TARS / UI-TARS-desktop** | 字节 [github.com/bytedance/UI-TARS](https://github.com/bytedance/UI-TARS) | Apache-2.0，2B/7B/72B，Qwen2-VL 底座；AndroidWorld 64.2；动作集含 open_app/press_home/scroll/tap | 可自托管做兜底视觉定位；7B 在家电上可跑 |
| CogAgent | 清华 THUDM | 视觉 GUI agent，9B | 备选 |
| Mobile-Agent-v3 / GUI-Owl | 蚂蚁 X-PLUG [github.com/X-PLUG/MobileAgent](https://github.com/X-PLUG/MobileAgent) | 开源模型 + TRPO RL | 参考，不必搬 |

- 优点：不用写规则，长尾界面也能走。
- 缺点：每步 1~4s、贵；要自托管 VLM 或调视觉 API；电视在播视频时截图里全是动态画面，识别噪音大。

### B 派：模块化 agent（读无障碍树，不靠看图）
| 项目 | 要点 |
|---|---|
| **AppAgent / AppAgentX**（HKU，[appagent-official.github.io](https://appagent-official.github.io/)） | 开源；把界面元素当"词汇"学；带 grid overlay 点任意坐标 |
| mobile-tester-agent | `uiautomator dump`→XML→剥掉 index/class 等噪音→算 bounds 中心→tap/swipe |

### C 派：轻量 ADB 桥（最贴近 TVPilot 形态）⭐
| 项目 | 要点 |
|---|---|
| **agent-droid-bridge**（Neverlow512，PyPI `agent-droid-bridge`，MCP server） | `snapshot_ui`→token、`detect_ui_change`、`get_screen_elements`（返回结构化元素+坐标+tappable/interactive）、`get_screen_text`、`wait "text"`。**这就是我们要补的 `/api/a11y/dump` 的开源参照。** |
| agent-droid（npm） | snapshot→ref→act，refs 每屏刷新，`wait text` 阻塞等待 |
| **ghost-in-the-droid/android-agent** | 纯 ADB 不装 App、无残留；50+ 方法（tap/swipe/type/clipboard/shell/intent）；按 App 定义 skills，dashboard+API |

## 对 TVPilot 的直接启示

1. **高频动作别让 LLM 走**：换台/切 App/音量/home 已是确定性 1~2s 直注，继续走数字键和脚本，不进 LLM 循环。
2. **关键缺口就是"读屏"**：照 agent-droid-bridge 的样子，在 TVPilot 加 `/api/a11y/dump`——跑 `uiautomator dump`→解析 XML→返回 `[{text, bounds, clickable, selected/focused}]`。LLM 据此"找节点→算要按几次方向键→确认"，不用看图猜。
3. **已知大坑（直接命中我们场景）**：`uiautomator dump` 在界面有持续动画/视频时**会失败**（主线程忙，MobileAgentBench 已证实）。我们电视正在播 IPTV 时 dump 不出来——**对策：只在菜单/选台/EPG/设置等静态界面 dump；播放中不读树，直接用已知频道号**。dump 失败自动回退 screencap + VLM（UI-TARS/豆包视觉）。
4. **"蓝图"不用手工画**：电视是 DPAD 树状导航，蓝图 = "目标节点文字 → 方向键步数 → 确认"，由 dump 出来的焦点位置自动算，不必人工录路径。Top 10 高频场景（进 EPG、切信号源、进设置、打开某 App 到某页）固化成带断言的脚本（到达后校验前台包名/节点文字）。
5. **延迟预期**：专用动作 1~2s；菜单导航每步 0.5~2s，多步任务 5~15s。别让 LLM 当遥控器盲按。

## 建议下一步（按优先级）
1. TVPilot 加 `/api/a11y/dump`（uiautomator dump 解析）+ `/api/a11y/wait_text`（阻塞等待元素出现）。
2. 把 5~10 个高频场景写成确定性蓝图脚本（带到达断言）。
3. 兜底：截图给豆包视觉模型/自托管 UI-TARS-7B 定位坐标，`input tap x y`。
4. butler 侧把"找节点→DPAD→确认"的循环接进工具，而不是每步都重新决策。
