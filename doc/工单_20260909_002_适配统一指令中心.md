## 一、背景

豆包管家已上线统一指令中心（command_store），PM 通过看板或工具创建指令（target=TP/DP），指令包含任务描述、优先级、截止时间。当前 TP/DP 不会主动拉取指令，需要 PM 通过消息管道手动通知。

**目标**：TP 实现定时轮询拉取待处理指令，接手/完成/失败时通过 API 上报状态，PM 可在看板实时跟踪 TP 任务进度，无需手动催办。

## 二、管家统一指令中心 API（已上线）

基础地址：`http://192.168.2.200:8095`
认证：请求头 `Authorization: Bearer admin`

### 2.1 拉取待处理指令

```
GET /api/commands/pull/TP
```

返回当前 target=TP 且 status=pending 的指令列表（按创建时间升序，一次拉取全部）。

响应：
```json
{
  "ok": true,
  "data": {
    "commands": [
      {
        "id": "CMD-20260909-0BAC",
        "target": "TP",
        "title": "修复 mytv 换台 API",
        "description": "详细描述...",
        "priority": "P0",
        "status": "pending",
        "created_at": "2026-09-09T10:00:00",
        "deadline": "2026-09-10T10:00:00"
      }
    ],
    "count": 1
  }
}
```

### 2.2 接手指令

```
POST /api/commands/{cmd_id}/accept
Content-Type: application/json
{"note": "已接手，预计今天完成"}
```

### 2.3 完成指令

```
POST /api/commands/{cmd_id}/complete
Content-Type: application/json
{"result": "已修复 mytv 换台 API，测试通过", "note": "可选备注"}
```

### 2.4 失败指令

```
POST /api/commands/{cmd_id}/fail
Content-Type: application/json
{"error": "错误描述", "note": "可选备注"}
```

### 2.5 查询指令详情（含事件历史）

```
GET /api/commands/{cmd_id}
```

## 三、实现要求

### 3.1 轮询机制

- 后台线程/进程每 **30 秒** 轮询一次 `GET /api/commands/pull/TP`
- 拉取到 pending 指令后，立即调用 `accept` 上报接手状态
- 轮询不影响 TVPilot 正常功能（异步后台线程，不阻塞主服务）
- 轮询间隔可配置（配置文件中设置，默认 30 秒）
- 启动时立即拉取一次（不等 30 秒）

### 3.2 状态上报

- 接手指令：调用 `accept`，note 中说明预计完成时间
- 完成指令：调用 `complete`，result 中说明完成内容
- 失败指令：调用 `fail`，error 中说明失败原因
- 每个指令的状态变更都要记录到本地日志

### 3.3 指令执行

- 拉取到指令后，根据指令 title/description 判断任务类型
- 执行对应操作（修复 bug / 开发功能 / 文档更新等）
- 执行完成后上报 complete
- 执行失败上报 fail
- 如果指令内容不明确或无法执行，上报 fail 并说明原因

### 3.4 防重复处理

- 已 accept/complete/fail 的指令不会再次出现在 pull 结果中（status 已变更）
- 本地记录已处理的指令 ID，防止重复处理（兜底）

## 五、验收标准

PM 在看板创建 target=TP 的指令后：
1. TP 在 30 秒内拉取到指令（日志可见）
2. TP 自动调用 accept，看板状态变为"进行中"
3. TP 执行完成后调用 complete，看板状态变为"已完成"
4. 失败时调用 fail，看板状态变为"已失败"，显示错误信息
5. 指令详情页可见完整事件历史（created→accepted→completed）
6. 轮询不影响 TVPilot 正常功能（电视操控/API 响应正常）
7. TVPilot 重启后自动恢复轮询
