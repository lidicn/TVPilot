# TVPilot 改进交接单

> 日期：2026-09-18
> 对接方：豆包管家 (doubao-butler)
> 目的：完善 llm_decide 主动决策场景的 TV 端交互闭环

## 一、需要新增的接口

### 1. Ask 聆听模式（最关键）

**现状问题**：TV 端语音听写需要先说唤醒词"豆包管家"才触发。但管家问完问题后（如"要不要打开电视？"），用户直接回答"好"是没有唤醒词的，TV 端不会听写，导致 ask 流程断掉。

**需求**：
```
POST /api/ask/listen
Content-Type: application/json
{
  "duration": 30,
  "room": "客厅"
}
```

行为：
- 进入聆听模式后，**不需要唤醒词**，直接听写用户语音
- 听写结果通过 MQTT 发布到 `tv/livingroom/wake`，格式同现有 voice_command
- duration 秒后自动退出聆听模式
- 如果已经在聆听模式，重复调用刷新 duration

```
POST /api/ask/stop
```
行为：立即退出聆听模式。

### 2. Ask 提示音

**现状问题**：管家问完问题后直接静音，用户不知道什么时候可以说话。

**需求**：
```
POST /api/ask/beep
```
行为：播一个短提示音（0.5 秒以内，"滴"一声），告诉用户"现在可以回答了"。
- 用系统音效即可，不需要 TTS
- 如果 TTS 正在播放，等 TTS 播完再播提示音

### 3. TTS 播放完成回调

**现状问题**：管家调 `/api/tts` 后不知道什么时候播完，无法精确开始聆听。

**需求**：
- `/api/tts` 响应里加一个 `duration_ms` 字段
- 或者播完后通过 MQTT 发布 `tv/livingroom/tts_done`

## 二、需要修复的问题

### 4. mytv 启动失败

**现象**：`POST /api/launch {"package":"com.tvcam.mytv"}` 返回 502 `mytv 不可达`。

**排查**：
- 电视在桌面 com.mitv.tvhome 时正常
- mytv 包是否安装？包名是否正确？
- ADB 连接是否稳定？电视息屏后 ADB 断开？

### 5. 电视息屏后 ADB 不可达

**现象**：电视锁屏时所有 API 都返回 502。

**需求**：TVPilot 应该能唤醒电视（通过 HDMI-CEC 或遥控器红外），唤醒后再执行操作。

## 三、完整 Ask 交互流程（目标）

```
管家 LLM 生成问句："要不要打开电视？"
  ↓
管家调 TVPilot /api/tts 播报问句
  ↓
TVPilot 播完 TTS
  ↓
TVPilot 播提示音 beep
  ↓
TVPilot 进入 ask/listen 模式（30秒免唤醒听写）
  ↓
用户说"好" → TVPilot MQTT 发布 voice_command
  ↓
管家收到回答 → 执行 tv_launch_app → TTS 确认
```
