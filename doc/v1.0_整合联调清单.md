## 二、v1.0 联调场景清单

### 场景 1：语音/文字换台

**目标**：用户说"换到中央一台"，管家调用 zap 工具，验证播放成功。

| 步骤 | 操作 | 验证点 |
|------|------|--------|
| 1 | 管家解析意图 → 调用 POST /api/zap {"channel":"中央一台"} | API 返回 ok=true |
| 2 | 等待 3-8 秒 | GET /api/current 返回 channel=中央一台, playing=true |
| 3 | 截图验证 | GET /api/screenshot，画面为中央一台节目 |
| 4 | 错误恢复 | 无效频道名 → 返回 invalid_parameter，管家提示用户 |

**验收标准**：换台成功率 ≥ 95%，换台到画面出现 ≤ 8 秒

---

### 场景 2：飞牛TV 搜索播放

**目标**：用户说"在飞牛TV播放流浪地球"，管家调用 combo_search_play。

| 步骤 | 操作 | 验证点 |
|------|------|--------|
| 1 | 管家调用 combo_search_play {"keyword":"流浪地球"} | API 返回 ok=true |
| 2 | 前台验证 | GET /api/foreground 返回 com.trim.tv |
| 3 | 播放验证 | GET /api/play_state 返回 playing |
| 4 | 中文输入验证 | tvremoteime 广播成功，搜索框显示"流浪地球" |

**验收标准**：搜索到播放全流程 ≤ 30 秒，中文输入正确

---

### 场景 3：系统控制（音量/回桌面/启动App）

**目标**：用户说"音量调到 50"/"回到桌面"/"打开 mytv"。

| 子场景 | 工具 | 验证点 |
|--------|------|--------|
| 音量调节 | keyevent KEYCODE_VOLUME_UP/DOWN | system_state 音量值变化 |
| 静音切换 | keyevent KEYCODE_VOLUME_MUTE | system_state is_muted 变化 |
| 回桌面 | combo_go_home | foreground = com.mitv.tvhome |
| 启动 App | launch_app {"package":"com.tvcam.mytv"} | foreground = com.tvcam.mytv |

**验收标准**：每个操作 ≤ 5 秒生效，状态查询正确

---

### 场景 4：多 App 切换

**目标**：mytv ↔ 飞牛TV ↔ 桌面 之间流畅切换。

| 步骤 | 操作 | 验证点 |
|------|------|--------|
| 1 | mytv 播放中 → launch_app 飞牛TV | 前台切换，mytv 后台保活 |
| 2 | 飞牛TV 中 → combo_go_home | 回到桌面 |
| 3 | 桌面 → launch_app mytv | mytv 恢复播放（HTTP 服务仍在） |
| 4 | 连续切换 5 次 | 无崩溃，HTTP 服务始终可达 |

**验收标准**：连续切换 5 次无崩溃，mytv HTTP 服务始终可达（保活服务生效）

---

### 场景 5：FaceID 个性化切换

**目标**：用户 A 站到电视前 → Arcface 人脸识别 → MQTT 推送 → TVPilot 切换用户 A → mytv 收藏列表同步为用户 A 的收藏。

| 步骤 | 操作 | 验证点 |
|------|------|--------|
| 1 | 用户 A 站到电视前 | Arcface 识别到用户 A，MQTT 发布 tv/livingroom/face |
| 2 | TVPilot 接收 MQTT 消息 | 相似度 > 0.5，触发 apply_user_profile |
| 3 | 用户切换 | GET /api/users 返回 current_user = 用户 A |
| 4 | 收藏同步 | GET mytv /api/favorites 返回用户 A 的收藏列表 |
| 5 | 5 秒去重 | 同一用户连续识别不重复切换 |

**前置条件**：Arcface 已注册人脸，引擎就绪（当前 registered=0, engine_ready=false，需用户配合）

**验收标准**：识别到切换 ≤ 3 秒，收藏列表正确同步

---

### 场景 6：观看历史查询（memory-agent 对接）

**目标**：memory-agent 通过 TVPilot API 获取用户观看历史，用于个性化推荐。

| 步骤 | 操作 | 验证点 |
|------|------|--------|
| 1 | 换台到多个频道 | mytv 自动记录观看历史（watchCount + lastWatched） |
| 2 | GET mytv /api/recent | 返回最近观看列表（频道/时长/次数） |
| 3 | GET TVPilot /api/history | 返回操作存档（ops.jsonl，含换台记录） |
| 4 | 数据格式 | JSON 结构化，含时间戳/频道/时长/用户 |

**验收标准**：观看历史完整记录，API 返回结构化数据

---

### 场景 7：智能观察（OCR/界面分类）

**目标**：管家不需要多模态截图，通过 OCR/ui_state 判断电视界面状态。

| 子场景 | 工具 | 验证点 |
|--------|------|--------|
| 界面文字识别 | GET /api/ocr | 返回界面所有文字+坐标 |
| 查找指定文字 | GET /api/ocr/find?text=xxx | 返回文字位置坐标 |
| 界面分类 | GET /api/ui_state | 返回首页/搜索页/播放页/设置页/弹窗 |
| 播放状态 | GET /api/play_state | 返回播放/暂停/缓冲/广告 |

**验收标准**：OCR 准确率 ≥ 90%，界面分类准确率 ≥ 85%，响应 ≤ 3 秒

---

### 场景 8：错误恢复与重试

**目标**：工具失败时，管家根据错误码做重试/换路径/报错决策。

| 错误场景 | 错误码 | 管家策略 |
|----------|--------|----------|
| 无效频道名 | invalid_parameter | 不重试，提示用户确认频道名 |
| 无效按键 | invalid_parameter | 不重试，提示有效按键列表 |
| 无效包名 | wrong_foreground | 先 launch_app 再重试操作 |
| 操作超时 | operation_timeout | 重试 1 次（指数退避） |
| 服务不可达 | unavailable | 重试 1 次，仍失败则提示电视离线 |
| mytv API 不可达 | mytv_api_error | 降级为 ADB 数字键换台，或提示启动 mytv |
| 内部错误 | internal_error | 不重试，记录日志，提示稍后再试 |

**验收标准**：所有错误场景返回正确错误码，管家 ReAct 能根据错误码做正确决策
