## TD-001 · ADB 掉线重连无最小间隔（退避）

| 项 | 内容 |
|---|---|
| 状态 | **OPEN**（已登记，⛔ 当前不改码） |
| 来源 | Chief 2026-11-15 15:3x 独立复跑 `ADB_RECONNECT_FIX_20261115` 后提出 |
| 引入 | `tvpilot/adb.py` 的 `adb_cmd` 在 `except OSError` 里立即 `adb_ready(force=True)` 重连，**无最小重连间隔** |
| 现象 | 电视关机／断电／Wi-Fi 长期离线时，每条命令都会撞一次 `adb get-state` + `adb connect`（各 3s/4s 超时上限） |
| 影响 | 批量命令连续卡在重连上——比原「状态永久卡死」好（不会悬挂、链路会自愈），但离线期会明显变慢；`adb_shell_output` 的 OSError 分支同理 |
| 建议默认取值 | 两次真实重连间隔 ≥3s；或连续失败次数递增退避（3s→6s→12s，上限 30s） |
| 回退口径 | 若出资人嫌离线期命令延迟高，可改为「仅首条失败命令立即重连、其余在窗口内复用上次结果」，或把退避做成可配置项 `TVPILOT_ADB_RECONNECT_BACKOFF_S`（缺省 3s）；**⛔ 不放松 `connected=False` 的断连标记**（否则回到原 bug） |
| 前置 | 改码需 Chief 放行；真机验证需出资人在场。当前 `commit` 仍不解禁（等 homesdk 发版日） |
| 验收判据 | 离线场景连续 N 条命令只触发 ≤1 次 `adb connect`（或按退避曲线），且 `connected` 保持 False、链路在电视恢复后首次命令自动重连成功；离线断言矩阵补「退避」分支，全绿且不减断言数 |
| 关联 | `data/reports/ADB_RECONNECT_FIX_20261115.md` §二；`tests/test_adb_reconnect.py`；`data/reports/AF_RECONNECT_MATRIX_20261115.json` |

> 备注：`_mark_disconnected()` 的「TimeoutExpired 不动 connected、OSError 才标记断连」判据已被 Chief 认可为正确，⛔ 加退避时不要把它合并回去（超时≠掉线）。
