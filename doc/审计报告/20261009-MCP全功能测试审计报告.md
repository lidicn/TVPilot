## 一、缺陷清单

### BUG-1 [严重] af_draft 泄漏 Python 内部异常

- 现象: af_draft 的 intent.when / intent.do 传字符串时抛未捕获异常
- 实际返回: {"ok": false, "code": "ADM_ERR_INTERNAL", "message": "工具执行出错：AttributeError: 'str' object has no attribute 'get'"}
- 期望: 返回参数校验错误(INVALID_PARAM)并指出具体字段
- 影响: 内部实现细节外泄; 调用方无法区分参数错与服务端故障
- 备注: af_test_submit 文档示例即为 {name, mode, when, do} 字符串写法, 与实际实现不一致

### BUG-2 [中] af_build 空 IR 错误码语义错位

- 现象: af_build(ir={}) 返回 ADM_ERR_INTERNAL
- 实际返回: {"ok": false, "code": "ADM_ERR_INTERNAL", "message": "工具执行出错：IRValidationError: IR 为空"}
- 期望: 空输入属用户输入问题, 应为 INVALID_PARAM / VALIDATION_ERROR

### BUG-3 [中] AutoForge 两条黄金路径 IR Schema 不一致

- af_build 要求图结构, 必填 ir_version / id / version / nodes / edges
- af_draft 与 af_compile_spec 产出规则式 {name, mode, when, if, do}
- 结果: 无法用 af_build 校验 af_draft 产物, 黄金路径 1 → 2 断裂

### BUG-4 [中] get_device_usage_summary Schema 与实现不符

- Schema: entity_id 声明可选, 无 required
- 实现: 传 days=1 返回 INVALID_PARAM: entity_id 不能为空（逗号分隔可传多个）
- 影响: Agent 按 Schema 构造调用必然踩坑

### BUG-5 [低] query_device_usage 报错参数名不一致

- 报错文案: 缺少 entity_id 或 logical_id
- 实际参数名: logical_device
- 影响: 误导调用方去传一个不存在的参数名

### BUG-6 [严重] 批量调用时 tool result body 被静默丢弃

- 现象: 并行批量调用时 tv_* / af_* / shell_status / list_members 等返回体仅含 {ok, summary, windowed:true, truncated:false}, detail/output 全部缺失
- 对照实验: 同一批工具单独调用时均返回完整 detail
  - tv_foreground 单独 → {"package":"com.xiaomi.tv.gallery"}
  - list_members 单独 → 3 名成员 lidicn / Kevin / Emily
  - af_catalog 单独 → total_entities 2890
  - tv_ui_dump 单独 → 4 个可交互元素
- 结论: 属扩展的结果透传/续跑窗口缺陷; truncated 仍报 false, 属危险静默失败
- 影响: Agent 会以为已取到数据而实际为空, 比显式报错更危险
