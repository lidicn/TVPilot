# 豆包管家 × TVPilot 对接路线变更（2026-09-08）

> **交接对象**：TVPilot 开发者
> **发起方**：豆包管家（脑）
> **背景**：TVPilot v0.2 工具层已就绪；豆包管家决定**自研轻量 Agent 框架**（ReAct 闭环），并统一模板体系到管家技能系统。
> **关联文档**：`tvpilot_agent_handoff.md`、`doc/ROADMAP.md`、`mytv_personalized_api_handoff.md`

---

## 一、核心决策（豆包管家侧已定）

1. **自研轻量 ReAct Agent**，不引入开源框架。Phase 1 起与 TVPilot 工具层联调（ReAct 闭环：Thought→Action→Observation→Adjust）。
2. **模板体系统一**：操作模板 / 经验的**存储、检索、执行、版本、沙箱**，一律由**豆包管家技能系统**承担。TVPilot **不再实现模板引擎**，**不再对接 memory-agent 模板存储**，**不再提供模板存储/检索/管理 API**（原 v0.3 方案废止）。
3. **可测试性**：双方为 ReAct 联调提供回放能力——管家侧 ReAct 轨迹（thought/action/observation）全量落库可回放；TVPilot 侧提供 `request_id` 维度的操作 + 截图存档（JSONL）。
4. 多模态成本：管家侧观察策略**结构化优先、截图兜底**；截图多模态账号后期扩容，不阻塞联调。

---

## 二、对 TVPilot 的路线调整

### v0.2（当前，无需改动）

- 已确认 12 个工具接口（screenshot/foreground/keyevent/tap/swipe/input_text/launch_app/wait/zap/current/channels/health）就绪，管家开始联调。
- ⚠️ **P0 阻塞项（需确认/解决）**：`tool_input_text` 对**中文**的支持。ADB `input text` 原生不支持中文与特殊字符（`tvpilot_server.py` 注释已注明），但核心验收场景「**启动飞牛TV → 搜索 → 播放**」的输入是**中文电影名/剧名**。请提供可靠中文输入方案（建议优先级：电视端剪贴板+粘贴广播 → 专用 IME → ADB 转码），否则该场景无法跑通。

### v0.3（原「场景模板引擎」→ **路线调整**）

- ❌ 取消：模板格式定义 / 模板执行引擎 / 模板本地缓存 / memory-agent 模板存储检索对接 / 模板管理 API / 内置模板库。
- ✅ 改为：**「场景组合动作 + 联调支撑」**
  1. 保留并沉淀**已验证的高置信组合动作**（如 `ensure_mytv_foreground` + zap、fongmi_search 等），作为原子工具的补充，**不承担模板编排/检索职责**（编排归管家技能系统）。
  2. **操作存档**：为每次 HTTP 工具调用记录 `(ts, request_id, tool, params, ok, error, cost_ms, foreground_before, foreground_after, screenshot[可选])` 追加写入 JSONL（`/data/tvpilot_ops.log` 或本地 `ops.jsonl`），供管家联调回放与问题复盘。
  3. 可选：`GET /api/history?limit=N&request_id=xxx` 查询最近操作存档，便于联调对账。

### v0.4 / v0.5（不变，且优先级不变）

- 无障碍服务（控件级操作）、OCR / 界面状态识别照旧推进——两者都降低管家多模态依赖、提升状态观察可靠性，与管家「结构化优先」策略一致，鼓励尽早落地。
- v0.5 的 `ui_state`（界面状态分类）对 ReAct 观察价值高，建议提前。

## 三、与管家联调的约定

### 3.1 通信

- **HTTP 主通道**（同步工具调用）；**MQTT 仅状态推送 + 回执**。换台已走 `request_id` 回执闭环（2026-09-07 已上线），保持兼容。

### 3.2 观察策略（管家侧执行）

- 优先结构化状态：`foreground` / `current` / `health`；
- 关键节点才截图：`screenshot?fmt=json&width=480`（压缩减 token）；
- 失败排查时必截图。

### 3.3 错误码重试矩阵（管家侧执行）

| 错误码 | 管家动作 |
|--------|---------|
| `tv_unreachable` | 重连重试，最多 3 次 |
| `app_not_responding` | 等待 2s 重试，最多 2 次 |
| `wrong_foreground` | 重新 `launch_app` |
| `operation_timeout` | 重试 1 次，仍失败则报错 |
| `invalid_parameter` | 不重试，直接报错 |
| `mytv_api_error` | 检查 mytv 后重试 1 次 |

### 3.4 建议 TVPilot 侧补充（低成本、高收益）

- `zap` / `launch_app` 响应已含 `foreground_after`，请保持（结构化验证，省截图）；
- 工具保持**确定性、幂等、串行锁**（现有 `_CMD_LOCK` 已是），避免并发 ADB 交错；
- 响应统一带 `cost_ms`，供管家估算延迟。

## 四、联调验收场景

1. **换台**：`"换到湖南卫视"` → zap → 验证 current/foreground；
2. **搜索播放**：`"在电视上播放《流浪地球2》"` → launch_app(飞牛TV) → 搜索 → 输入中文 → 回车 → 播放（**中文输入是硬门槛**）；
3. **回桌面/兜底**：操作异常时 `keyevent KEYCODE_HOME` 逃生，验证可恢复。
