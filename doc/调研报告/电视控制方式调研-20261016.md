# TVPilot 控制电视方式调研报告

> 调研时间：2026-10-16
> 目的：对比开源项目，找出 TVPilot 不好用的原因和改进方向

---

## 一、主流开源项目怎么做

### 1. Mobile MCP（7K Star，最火）

**GitHub**: mobile-next/mobile-mcp
**技术栈**: ADB + 无障碍树（Accessibility Tree）

**核心设计**：
- **无障碍优先**：直接读 Android 无障碍树，不需要截图和视觉模型
- **降级到截图**：当无障碍树读不到时（游戏、Flutter），才用截图 + 坐标点击
- **ADB 连接**：不需要在设备上装 APK，直接用 ADB

**工具列表（30+ 个）**：
- 设备管理：列设备、屏幕尺寸、方向、定位、剪贴板
- App 管理：列 App、启动、终止、安装、卸载
- 屏幕交互：截图、列元素、点击、双击、长按、滑动
- 输入导航：输入文字、按键、打开 URL
- 日志崩溃：日志、崩溃报告、批量命令

### 2. Android Accessibility MCP

**技术栈**: 无障碍服务 APK + 本地 HTTP server

**核心设计**：
- 在设备上装一个 APK，开启无障碍服务
- 用 AccessibilityService.takeScreenshot() 截图（Android 11+）
- 用无障碍服务读 UI 树
- 节点 ID 用 SHA-256 哈希生成稳定 ID

**优点**：直接在设备内操作，快

### 3. AndroidAgentBridge

**技术栈**: 无障碍服务 APK + Ktor HTTP server

**核心设计**：
- 设备上跑一个 MCP server
- 无障碍服务读 UI 树、派发手势
- 支持 tap、swipe、text input、intent launch

### 4. UFO³（Microsoft 开源）

**技术栈**: ADB + MCP

**核心设计**：微软背书，企业级，复杂

## 二、TVPilot 当前方式 vs 主流方式

| 对比项 | TVPilot（现在） | 主流项目 | 差距 |
|--------|----------------|----------|------|
| **UI 树** | `uiautomator dump` | 无障碍树 | TVPilot 慢，且读不到 Flutter/WebView |
| **截图** | `screencap` 命令 | 无障碍 API / screencap | 差不多 |
| **点击** | `input tap x y` | 按元素 ref / 坐标 | TVPilot 只能坐标，主流可以按元素 |
| **输入文字** | `input text` | 直接 setText 到输入框 | TVPilot 中文输入有问题 |
| **批量操作** | 每次一个命令 | 一次调用执行多个 | TVPilot 慢，往返多 |
| **设备内 Agent** | 无（纯远程 ADB） | 有的有（APK + 本地 server） | TVPilot 每次都要网络往返 |

## 三、TVPilot 不好用的根本原因

### 1. 纯 ADB 命令行方式太慢

每次操作都要：
```
TVPilot → ADB shell → 执行命令 → 返回结果
```

主流项目用无障碍服务，直接在设备内操作，没有网络往返。

### 2. UI dump 质量差

`uiautomator dump` 只支持原生控件，读不到：
- Flutter App
- WebView
- 游戏
- 自定义 View

这就是为什么很多界面"看不到元素"。

### 3. 中文输入有问题

`input text` 命令不支持中文，需要用 tvremoteime 输入法复制粘贴。
主流项目直接 setText 到输入框，中文没问题。

### 4. 没有批量命令

每次点击、每次输入都是一个独立的 ADB 命令，往返太多。
主流项目支持一次调用执行多个操作（比如：点击 → 输入 → 回车）。

## 四、TV 端的特殊挑战

电视和手机不一样：

1. **没有触摸**：只有遥控器（方向键、确认键、返回键）
2. **焦点导航**：电视 UI 是为遥控器设计的，焦点很重要
3. **很多 TV App 是 WebView/Flutter**：uiautomator dump 读不到
4. **换台是核心功能**：手机没有，TVPilot 有

## 五、改进方向（按优先级）

### P0：立竿见影（不用装 APK）

1. **批量命令工具**：一次调用执行多个操作（点击 → 输入 → 回车）
   - 减少网络往返，速度翻倍

2. **更好的输入方式**：用 `adb shell input keyevent` + 剪贴板
   - 先把文字放到剪贴板，再粘贴
   - 解决中文输入问题

3. **更好的 UI dump**：用 `uiautomator dump` + 解析优化
   - 过滤不重要的节点
   - 生成稳定的元素 ID

### P1：装 APK（效果最好）

4. **在电视上装一个 Agent APK**：
   - 开启无障碍服务
   - 直接读 UI 树（比 uiautomator dump 快且全）
   - 直接 setText 到输入框（中文没问题）
   - 本地 HTTP server，远程调用

### P2：长期优化

5. **焦点管理**：电视是焦点导航，不是触摸
   - 方向键移动焦点
   - 确认键点击

6. **截图优化**：
   - 直接在设备内截图，不用 pull
   - 更小的体积，更快的速度

## 六、推荐方案

**短期（1-2 天）**：
- 加批量命令工具
- 改输入方式（剪贴板粘贴）
- 优化 UI dump 解析

**中期（1-2 周）**：
- 在电视上装 Agent APK
- 用无障碍服务读 UI 树
- 直接 setText 输入

**长期**：
- 参考 Mobile MCP 的工具列表，补充缺失的工具
- 加日志、崩溃报告等调试工具
