# TVPilot 路由分发迁移计划（阶段3）
> 状态（2026-11-12 整理）：**已取代／过期**。本文是当时的记录，勿当作现状；现行口径见 `doc/README.md` 真源优先级表。

## 现状
- `TVPilotHandler` 类约 860 行（:502-1360），占主文件 63%
- 辅助方法 5 个：`_json`, `_send_png`, `_serve_static`, `_read_body`, `_handle_tool`（约100行）
- `do_GET` 约 480 行，35+ 路由
- `do_POST` 约 270 行，25+ 路由
- 总计 60+ 路由端点

## 迁移策略
采用**路由表+处理函数**模式，将 `if/elif` 链改为路由表查找。

### 目标结构
```
tvpilot/
  routes/
    __init__.py      # 路由表注册 + handle_get/handle_post 分发
    iptv.py          # /iptv/*, /api/iptv/*, /api/channels, /api/epg
    control.py       # /api/zap, /api/keyevent, /api/tap, /api/swipe, /api/input_text, /api/launch_app, /api/wait, /api/combo/*
    a11y.py          # /api/a11y/* (19个路由)
    media.py         # /api/screenshot, /api/analyze, /api/ocr, /api/tts, /api/audio/*
    state.py         # /api/health, /api/foreground, /api/current, /api/ui_state, /api/play_state, /api/system_state
    users.py         # /api/users, /api/users/switch, /api/face/*
    remote.py        # /remote, /remote-static/* (PWA)
    legacy.py        # /channels, /active, /zap, /screenshot, /fongmi/search, /keyevent, /tap (旧版兼容)
    ask.py           # /api/ask/* (远场语音)
```

### 处理函数签名
```python
def handle_xxx(handler, path, q):  # GET
    """返回 True 表示已处理，False 表示未匹配"""
    ...

def handle_xxx_post(handler, path, body):  # POST
    """返回 True 表示已处理，False 表示未匹配"""
    ...
```

### 路由表
```python
GET_ROUTES = [
    ('/remote', remote.handle_remote),
    ('/api/health', state.handle_health),
    ...
]

POST_ROUTES = [
    ('/api/zap', control.handle_zap),
    ...
]
```

### 分发逻辑
```python
def handle_get(handler, path, q):
    for pattern, func in GET_ROUTES:
        if path == pattern or (pattern.endswith('*') and path.startswith(pattern[:-1])):
            if func(handler, path, q):
                return
    handler._json({'ok': False, 'error': 'not found'}, 404)
```

## 迁移顺序（按风险从低到高）
1. **routes/iptv.py**（最独立，仅依赖 fetch_iptv_source/fetch_epg/generate_channel_logo）
2. **routes/state.py**（健康检查+状态查询，只读）
3. **routes/media.py**（截图/分析/OCR/TTS/音频）
4. **routes/users.py**（用户/FaceID）
5. **routes/remote.py**（PWA 静态文件）
6. **routes/legacy.py**（旧版兼容路由）
7. **routes/control.py**（核心控制，换台/按键，风险高）
8. **routes/a11y.py**（无障碍，19个路由，量大）
9. **routes/ask.py**（远场语音）

## 每步验证
- 迁移一个路由模块后，py_compile 验证
- 部署后 curl 测试该模块的所有路由
- 确认未迁移路由仍正常工作

## 风险
1. **路由顺序依赖**：当前 if/elif 链有顺序（如 /api/a11y/* 排除在通用鉴权之外），路由表需保留优先级
2. **_handle_tool 依赖**：很多 POST 路由用 `self._handle_tool()`，需保留在 handler 中或提取为公共函数
3. **路径遍历防护**：/remote-static/ 的路径遍历检查需保留
4. **旧版兼容路由**：/zap, /channels 等旧路由需保留

## 预期成果
- TVPilotHandler 从 860 行降至约 150 行（仅辅助方法+分发）
- 主文件从 1363 行降至约 650 行
- 路由按功能域组织，新增路由只需在对应模块添加
