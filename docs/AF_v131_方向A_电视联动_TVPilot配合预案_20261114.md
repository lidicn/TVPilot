## 四、D3 新闻编排全链端点（一期核心件，纯 A）

内部编排函数（由 `button.tv_morning_news` 触发；⛔ 不做 HTTP 直调）：

```
1. 唤醒：miIO set_power → 退 WoL → 退插座 → 全失败 ⇒ result=wake_fail 返回
2. ADB 探测（四元）
   ├─ off ⇒ 开电视已完成 ⇒ result=adb_off_tv_on 返回（AF 播降级提示，话术不变）
   └─ ok ↓
3. am start IPTV（全屏）  ← 一期无 ArcFace／tvdesk／faceid 段
4. 选台 CCTV1（三路径按实测排序：deeplink／数字键／LLM 视觉）
5. result=iptv_ok；发布 result 传感器＋逐步回执 {steps:[{step,status,evidence}],total_ms}
```

**`iptv_ok` 发布口径（G1 裁定解禁）**：电视亮＋IPTV 全屏＋中央一台**同帧已验证**才发布（S3＝IPTV、S4＝中央一台；⛔「发了命令」＝「成功了」）。S4 取数注意 `/api/current` 慢一拍：换台后 `LastchannelID` 最长约 6s 才写回（AGENTS.md 在案），须等待并交叉 `/api/play_state`＋前台包名＋截图后确认；未确认即 `unknown(reason=timeout/capture_failed)`，⛔ 猜。S7 同帧解除。终态必达 240s、ADB-off 降级话术不变。

**一期休眠值**：`faceid_timeout`／`arcface_fail` 枚举保留、无生产路径触发；AF 静默不播报、仅留痕、⛔ 重试。二期复用时语义见契约 v2.1 §二。

选台三路径都要实测逐条留证；数字键路径 11-13 真机两次全绿（`data/reports/ZAP_VERIFY_20261113.md`），deeplink／LLM 视觉两路径等窗口。
